✦ SQUARE POS IDENTIFICATION

How does Relay know it's you?

Square can link repeat purchases to a merchant's customer profile and card fingerprint. Relay needs one independent, verified connection to that customer before it can safely show their receipts.

This is an interactive architecture demonstration, not a real Square identity-verification service.

The proposed 3-step flow

1. Shop normallyRetailer takes card payment on Square. Relay does not replace checkout.
2. Link onceCustomer proves ownership through a retailer-authorised account or secure order claim.
3. Match next timeMerchant-scoped Square IDs enable repeat recognition, subject to conflict checks.

Simulate the first verified link

All four simulated payments deliberately end in 5858, just like our prior Sandbox tests. The distinct customer IDs and fingerprints shown here are hypothetical, not values returned by that Sandbox run.

Clicking “Simulate verified link” does not authenticate anyone. A production app would have to verify that claim on the retailer's server before creating this record.

What our real Square test must establish

The GitHub Actions audit checks recent actual Square Sandbox payments for payment.customer_id, card_details.card.fingerprint, order_id and repeated fingerprints. It reports anonymised identifiers, not customer data.

Open Square POS audit in GitHub ↗

Important: a Square Sandbox API payment is not a physical POS terminal test. Fingerprints are merchant-scoped. Apple Pay can have a different fingerprint from the same physical card. A card ending in 5858 is not sufficient identity evidence.
